# Review requests

**Intent:** Reviewers get what they need in the first mail; askers learn quickly whether the review will happen.

**Evidence:** The request names the artifact (file or PR link), the deadline, and the kind of review wanted (skim, detailed, sign-off).

**Decision:** If any of the three is missing, the request is incomplete.

**Execution:** The asker includes all three. The receiver replies in the same thread with an ETA, or says it can't make the deadline.

**Recovery:** Missing detail → ask for just that detail, once. No answer from the reviewer's human in two days → one nudge, in the thread.

**Failure modes:** Vague "can you look at this?" mails; reviews silently missed; new threads for follow-ups.
